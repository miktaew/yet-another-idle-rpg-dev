# Translation handbook

How player-facing text works in this game, and the rules for translating it.

Turkish counterpart: [I18N.TR.md](I18N.TR.md).

---

## 1. How it works

Player-facing text is never written in `src/`. Dialogue **structure** lives in
`src/dialogues.js`; the **text** those nodes display lives in
`locales/<language>.js` behind a string id.

- `src/translation.js` holds `translationManager`. `init(language)` loads that
  locale and, for any language other than the default, also loads the default so
  there is something to fall back to. `getText(language, id)` resolves one id.
- The locale object is a **flat, single namespace**. It is assembled from sections
  at the bottom of the file (`{...racial, ...ui, ...stats, ...skills, ...bio}`) and
  exported as the default. The sections are for the reader's benefit only.
- `translateUI(language)` fills every element carrying a `data-translation`
  attribute. Everything else goes through `getText` when its panel is drawn.
- A missing id falls back to the default language and logs a warning once. So a
  partial locale is safe: untranslated text shows in English rather than as a
  placeholder.
- `npm run check` prints the reference key count and each locale's coverage.
  Unknown keys are an error; missing keys are a warning. `LOCALE_STRICT=1` makes
  missing keys fatal.

### Racial text variants

An id prefixed with `mofu#` is the variant shown when the beastkin flag is set.
Resolution happens **per language**: a language that has the base text but no
variant answers with its own base text rather than borrowing the other language's
variant, because staying in the active language matters more than getting the
variant. A `mofu#` key with no base key can never be reached, and `npm run check`
treats it as an error.

### Adding a language

1. Create `locales/<name>.js` exporting a default flat object.
2. Register it in `languages` in `src/main.js`, and give it a display name in
   `language_names` — each language names itself in its own language.
3. That is all. The selector in the options panel is built from `languages`, and
   the choice is already saved and restored with the rest of the save data.

The selector switches live. `translateUI` updates the static chrome immediately;
dialogue, tooltips and quest text update as their panels are redrawn. **A newly
added locale file is invisible in bundle mode until the next build** — esbuild
globs `locales/` at build time. Dev mode fetches it at runtime.

## 2. Hard rules

### Never translate a key

Keys are simultaneously lookup ids and, for content registries, **save data**.
Translating a key is the same operation as renaming it, and renaming one silently
breaks existing saves. Only values are translated.

This is why the `skills` section maps skill ids to shown names: the key
`"Shield blocking"` stays exactly as it is, and only the value changes.

### Translate meaning and tone, not words

The result must read as though it had been written in the target language. Rewrite
sentence structure freely — English word order, punctuation habits and paragraph
rhythm are not binding. What must survive is the meaning and the register.

Not acceptable: machine-translation phrasing, calques, idiom translated
word-for-word, or the wrong sense of a word that has several.

> "Spider web" is a **web of silk**, not a computer network. Resolve the sense
> against the in-game context before choosing a word.

### Translate in context units

A string is read on screen underneath whatever is above it. The unit of
translation is therefore the screen region, never the individual string:

- a player question **together with** the reply that answers it;
- a stat's short form **together with** its long form — the tooltip has to name
  the same thing the row abbreviates;
- a dialogue's description **together with** the lines it introduces;
- a label **together with** the values that can appear after it (`"Height"` +
  `"Short"` must read as one line).

Nothing below may contradict or drift from what is above it.

### Keep the voice

Read [STORY.md](STORY.md) section 4 before translating narrative text. The register
is wry-cozy over a grim substrate: comedy carries the weight, the horror is ambient.
A translation that is accurate but flat has failed.

Stage directions are written `*[like this]*` and that convention is kept in every
language.

### Improve only where the original is merely terse

Where English left an abbreviation unexpanded and the long form adds nothing
(`"EP"` for both forms), spelling it out in the target language is right — it is
clearer and still faithful. Do not use this as licence to add information the
original does not carry.

## 3. Turkish specifics

### Address register

Mixed, per NPC. The map is in [STORY.md](STORY.md) section 6. It is an authoring
convention, not an engine feature: each line is a separate id, so the register is
written into the line. Do not try to make it runtime-selectable.

### Dotted and dotless i

`toUpperCase()` and `toLowerCase()` are not locale-aware in this codebase, and
Turkish `ı`/`i` do not map the way the default locale assumes. Concretely: the
capital of `ırk` is `Irk`, not `İrk`. Where the game capitalises a translated
string itself — `capitalize_first_letter` in `src/misc.js` — check the result for
any word starting with `ı` or `i`.

### Sentences assembled from fragments

Turkish is agglutinative and its word order differs, so a sentence built by
concatenating an English fragment with a name cannot be translated correctly. Where
that happens the fragment has to become a parameterised template before it can be
localised. Report these rather than working around them.

### Plurals

Turkish does not pluralise a noun that follows a number. "3 items" is
"3 eşya", not "3 eşyalar". Where the English text does naive `s`-suffixing or
`item(s)`, the Turkish form usually needs no marker at all.

### Races and proper nouns

Race names that are Japanese loanwords stay as they are: **Nekomimi**,
**Inumimi**, **Nezumimi**, **Kitsunemimi**. Their alternative names translate
(`Cat person` → `Kedi insan`). `Lizardkin` becomes `Kertenkele soylu`.

Per [STORY.md](STORY.md) section 5, proper nouns are reserved for peoples, places,
materials and the mythic. Those are **not** translated — Snake Fang Tribe, Carya
Canyon, Atratan, Ratzor Rathai keep their form. Descriptive names are translated.

## 5. Known gaps

These are places where text is not yet reachable by the translation system at all.
None of them are a translator's problem to work around; they need a code change
first.

- **`help.html` and `changelog.html`** have no translation hooks and no container to
  attach one to. Together they are the largest English surface in the repository.
- **Item, location and enemy display names** are their registry keys. Translating
  them requires a display-name indirection layer, so that each entry keeps its
  English key forever and gains a separate id for its shown name. Tracked in
  [PROPOSALS.md](PROPOSALS.md).
- **Log messages** emitted from `src/` are literal English strings. The
  `rewards.messages` field is the exception and now takes ids.

Quest names, descriptions and task descriptions used to be here. They now live
behind ids under the shape `quest <quest_id> [name | desc N | task N]`, and
`npm run check` verifies every declared id resolves.

## 6. Working on a translation

1. `npm run check` — see where the coverage stands.
2. Pick a whole context unit, not a row of the missing-keys list.
3. Read the English text **and** its neighbours before writing anything.
4. Write the translation, then reread it on its own without the English. If it
   reads like a translation, it is not finished.
5. `npm run check` again — an unknown key means a typo in an id.
6. `npm test` — the fallback and lookup behaviour is covered there.
7. Boot the game, switch the language in the options panel, and look at the actual
   screens you touched.
